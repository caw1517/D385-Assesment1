# Domain docs

Use a single-context layout: root CONTEXT.md and docs/adr/.

Before exploring the codebase, read CONTEXT.md and ADRs relevant
to the area being changed. If absent, proceed silently.
Create domain documentation through domain-modeling as terms
and decisions are resolved.

Use the vocabulary defined in CONTEXT.md when naming domain
concepts. Reconsider unfamiliar terms or note genuine glossary
gaps for domain-modeling.

Explicitly flag proposals that contradict an existing ADR,
identifying the ADR and the reason to revisit it.
